30-second summary

RepoGrounding Plus tests whether Coeus AI can answer harder repository questions using the current project files as evidence. The benchmark focuses on source-grounded reasoning rather than autonomous code repair: it checks whether the assistant can trace runtime flow, identify exact symbols, compare source responsibilities, preserve context across follow-up turns, refuse unsupported claims about absent features, avoid accidental patch/diff routing, and keep private trace machinery out of user-facing answers.

Benchmark framing

This is a codebase-context benchmark, not a full SWE-bench style autonomous issue-resolution test. It measures whether the app can load a repository and answer harder engineering questions from source files without losing context, inventing unsupported features, misrouting semantic questions into patch/diff mode, or exposing internal trace machinery.

Compiled-turn framing

The evaluation is backed by Coeus AI's compiled-turn runtime. Each user request is converted into a traceable unit before retrieval, prompt packing, model execution, validation, and export consume it.

1. Intent / contract What kind of answer is allowed?
The turn is classified into an answer contract such as source-order tracing, source-usage tracing, architecture explanation, semantic comparison, or general chat. The contract decides whether source evidence is required and whether patch/diff behaviour is allowed.
2. Retrieval policy What evidence may enter?
The retrieval layer receives policy truth from the turn compiler. It decides whether to use focused source files, broad project retrieval, strict source evidence, semantic primers, inventory, or scan-reinforced evidence.
3. Lattice packing Which planes actually entered the prompt?
Coeus separates source evidence, inventory, plan/context, continuity, recent mutation state, and tool observations. The packed prompt records which planes were admitted and which were withheld.
4. Execution Model path or deterministic path?
Host-control commands can be served deterministically. Repository QA turns are usually sent to the model with a contract, source evidence, and prompt markers attached.
5. Validation Did the answer satisfy the contract?
The validator checks the final answer against the canonical contract. For source-required turns, it verifies that source evidence was present and satisfied rather than letting the answer rely on unsupported memory.
6. Export What proves what happened?
A private headless trace bundle records the compiled policy, retrieval posture, packed planes, source-evidence counts, validation outcome, and final answer reference. Public reports summarize the safe evaluation result without exposing private runtime internals.

What this benchmark checks

  • Source-order tracing: follows execution from process entry through one completed runtime turn.
  • Exact-symbol grounding: checks details such as boundary guards, grid variables, and runtime state propagation.
  • Semantic comparison: compares source files by responsibility without treating the request as a diff.
  • Negative grounding: identifies absent persistence, combat, and item wiring without hallucinating implementation.
  • Multi-turn continuity: preserves repository context across follow-up turns.
  • Artifact suppression: avoids exposing internal trace, vector, project, or agent storage paths.
